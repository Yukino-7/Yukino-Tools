# AI API 调试：cURL 与 SSE 设计草案

状态：当前实现与早期设计参考。更新：2026-10-30。

当前实现已将原 cURL 页面整合到 AI API 调试。收藏沿用原有文件，支持搜索、载入、更新、重命名、另存与删除；发送和停止位于顶部，来源终端默认自动识别，手动选择与解析参数收在设置中。cURL 终端转换通过按钮打开独立弹框，不再常驻主界面，原独立 cURL 导航入口迁移到 AI API 调试。

普通 JSON 返回有保留数值精度的格式化视图、原文与响应头，支持复制和 JSON 导出；HTML、文本、错误响应和空响应均可查看。SSE 保留既有协议聚合、Markdown、事件检索、原始流、停止、超时和离线导入。传输格式不由 AI 解析模式强制决定，选择通用 SSE 内容解析不会把普通 JSON 当作事件流。

独立 Body JSON 编辑和带到达时间的调试包回放仍未实现。以下章节保留早期目标设计，以当前 README 使用说明与源码为准。

## 1. 目标与入口

核心流程：粘贴一条 cURL → 检查请求 → 点击发送 → 实时查看合并结果和 SSE 事件 → 定位错误或导出结果。

在 AI 分组增加「AI API 调试」，支持搜索 curl、SSE、stream、流式、接口调试。原「cURL 生成与转换」继续承担命令构建与终端格式转换，并提供「在 AI API 调试中打开」入口，只传递内存中的请求，不自动发送。

新页面以 cURL 编辑为主。复用现有 `CurlCommandParser`、`CurlCommandPlan` 和编辑器组件，增加独立的执行计划校验层。解析成功不等于可以执行：现有转换器可以保留文件等选项，执行器必须再次检查能力边界。

## 2. 页面布局

宽窗口使用左右可调分栏：左侧约 40% 编辑请求，右侧约 60% 查看结果。窄窗口切换「请求 / 响应」，避免挤压编辑器。保留 App 现有视觉与快捷键习惯。

```text
AI API 调试                              [载入示例] [导入流记录]
────────────────────────────────────────────────────────────
请求                            │ 响应
[来源终端 ▾]                    │ HTTP 200 · 接收中 · 已收 42 个事件
                                │ 首事件 320 ms · 首文本 650 ms
curl https://…                  │ 总耗时 3.2 s · 8.4 KB
  -H 'Authorization: …'         │
  -H 'Content-Type: …'           │ [结果] [事件] [原始流] [响应头]
  -d '{… "stream": true …}'     │
                                │ 正文持续追加……
POST · host.example /v1/…        │
[Body JSON] [变量 1] [高级]      │ 工具调用 1 / 提供方返回的思考内容
解析：自动（可手动切换）         │
[发送 ⌘↩] [停止]               │ [复制正文] [导出 ▾]
────────────────────────────────────────────────────────────
请求状态 / 参数问题 / SSE 诊断 / 完成或中断原因
```

请求编辑：

- 粘贴后仅自动解析，显示方法、目标主机和路径；点击发送才请求。
- 支持现有 Bash/zsh、Windows CMD、PowerShell 来源格式，最终在 macOS 上规范执行。
- 「Body JSON」打开独立 JSON 编辑区；只有请求体能无损定位时才允许编辑，应用时更新对应参数，不重写其他参数或数字精度。
- 不自动添加 `stream: true` 或改请求协议；识别到适用的 JSON 请求缺少流式开关时，提供显式修改操作。
- 模板使用占位模型名、地址和凭据。支持 `{{API_KEY}}` 等显式变量及安全输入框，不执行 `$()`、反引号或 shell 展开；常见 `$API_KEY` 用法提示转换为显式变量，不猜测单引号中的字面值。
- 高级设置包含连接超时、无数据超时、可选总时限和解析模式。显式 cURL 超时优先，页面展示生效值及来源，调整后明确覆盖。
- 点击发送冻结本次请求快照；运行中修改输入只影响下一次请求。首版同页只允许一个活动请求。

## 3. 响应的四个视图

### 结果

已支持 Dify 的 message / agent_message / text_chunk / message_replace 与工作流结果，过滤心跳；通用 SSE 自动提取常见 answer/content/text 字段及 response/responseAll 增量与累计回答，仍支持手动路径覆盖。返回的 reasoning、exec_thought 与 `<think>` 内容折叠显示，复制和导出的正文不包含思考内容。接收期间尚无正文时，执行/思考过程默认展开并提示正在等待正式正文；正式回答到达或请求结束后默认收起，手动展开/收起优先。

- 正文默认渲染 Markdown（标题、列表、引用、表格、代码块），可切换源码；正文按 150 ms 节流解析，代码块可单独复制。
- 提供方实际返回的 reasoning/thinking/摘要作为独立可折叠内容，不推断或生成未返回的内容。
- 工具调用按 choice、item、content block、tool index/ID 分组，展示函数名、参数片段与完成状态。未完成参数先按文本展示，完成后再校验 JSON；仅查看，不执行工具。
- 多个 choice 或输出项分别展示，不拼成同一个答案。
- 展示模型、完成原因和提供方返回的 usage。缺失显示「未返回」；各协议按自身累计/增量语义更新，不把每次累计计数相加。
- 内容提取失败时提示并保留其他视图；普通 JSON、文本或 HTML 响应仍可查看。

### 事件

- 虚拟化事件列表：序号、相对到达时间、与上一事件间隔、event 名、id、data 大小、摘要。
- 点击展开完整 data，JSON 美化和原文可切换；非 JSON data 同样是合法 SSE 内容。
- 支持查找、按 event 类型过滤、复制单条；可隐藏心跳。注释心跳作为诊断记录，不伪装成派发的 SSE 消息。
- 自动跟随最新事件，用户上滚后暂停跟随，提供「回到最新」。暂停滚动不暂停网络读取。
- 显示「最后收到字节」和「最后收到正文」的间隔，区分心跳仍在但内容停滞。

### 原始流

- 展示 cURL 输出的响应体文本，保留 SSE 行、注释、空行和未完成尾部；这是传输解码后的响应体，不宣称是原始 HTTP 报文、TLS 字节或服务器网络分块。
- 传输读取批次与 SSE 事件数量独立统计，不能用读取次数代替事件数。
- 可将导出的响应体重新导入解析，无需再次调用模型。只有带记录时间的调试文件才能恢复原到达间隔；普通 `.sse` 文件只按顺序解析。

### 响应头

- 展示状态码、Content-Type、request ID、限流等实际返回的头；重定向和中间响应单独标记。
- 非 2xx 也保留响应体，便于查看 401、429 和网关 HTML 错误。
- cURL 退出码、网络诊断、HTTP 状态、SSE 解析状态、AI 协议完成状态分别呈现。

## 4. 协议适配

首版完成通用 SSE 与 OpenAI Chat Completions 兼容格式；同时设计独立适配接口，随后补 Responses 与 Anthropic，不用域名判断协议。

| 模式 | 行为 |
| --- | --- |
| 自动 | 结合响应头与事件结构识别；展示识别结果，允许手动覆盖 |
| 通用 SSE | 完整事件查看；可选简单字段路径，如 `data.content`，选择增量追加或累计替换 |
| Chat Completions 兼容 | 聚合 content、返回的 reasoning 字段、tool_calls，区分 choices，识别 `[DONE]` 与 usage |
| Responses（后续） | 按 item/content 索引处理文本、工具参数、完成、失败和 incomplete 事件 |
| Anthropic Messages（后续） | 按 content block 处理 text、返回的 thinking、工具参数，以及 message_stop/error |

通用字段路径只针对 SSE 的 JSON data，支持对象字段与数组索引，不引入完整 JSONPath。非 JSON、未知事件和适配失败保留原文，不丢事件。手动切换解析模式可基于已接收记录重新解析，不重新请求。

`[DONE]` 是特定 API 的约定，不是 SSE 标准结束标记。不能看到 `finish_reason` 就立即关闭连接，以免漏掉后续 usage。已知协议必须识别业务完成信号；连接正常关闭但缺少完成信号时标注「连接已结束，未收到完成标记」。通用 SSE 在 EOF 标记「连接已结束，业务完成状态未知」。

## 5. SSE 解析与流式体验

处理管线：

```text
cURL 响应体字节
  → 增量 UTF-8 / 行解析
  → SSE 字段与事件组装
  → AI 协议适配
  → 正文、工具调用、usage、结束原因
```

- 字节读取边界不等于 UTF-8 字符、行、SSE 事件或 JSON 边界；支持跨块中文、CRLF 拆分、同批多个事件。
- 遵循 UTF-8/BOM、LF/CRLF/CR、空行派发、多行 data 用换行拼接、冒号注释、id/retry 与字段首空格规则。
- EOF 前未以空行完成的事件仅放在「未完成尾部」诊断，不按完整 SSE 事件派发。
- 分开记录 SSE 格式诊断、事件 JSON 解析错误、内容适配错误。坏 JSON 不阻止后续通用事件接收。
- 展示连接中、等待响应、接收中、协议完成、连接结束、已停止、超时、失败等状态；收到 HTTP 200 后的流内 error 仍标记失败。
- 不自动重试或断线续传；记录 retry/id，但 AI POST 请求重发需要用户主动操作，避免重复生成与计费。
- 用户停止后保留已有内容，标记「用户停止」；超时保留内容和原因。停止界面更新与取消网络请求分开处理。
- UI 按约 30–60 ms 批量更新，事件列表虚拟化；原始缓存复用而非为四个视图各复制一份。
- 建议首版保护上限：响应体 20 MiB、事件 10,000 条、单事件 1 MiB、诊断 1 MiB。达到上限明确停止接收，保留已收数据并标记原因，绝不静默丢弃后继续声称完整。

## 6. 执行与凭据

建议使用系统 `/usr/bin/curl` 执行规范化请求，复用其代理、压缩和 HTTP 行为。通过 `Process` 启动固定可执行文件，不调用 shell；对系统 cURL 不支持的能力明确报错。

- 增加 `CurlExecutionPlan`，仅允许已审查的 HTTP(S) 请求选项；复用文本解析器但不直接执行其全部输出。
- 原始命令和实际执行摘要都可查看。执行强制禁用 `.curlrc`、关闭输出缓冲，隔离响应头、响应体和诊断输出；所有调整显式列出，不静默改变认证、方法、正文或重定向语义。
- `-i/-v/-o/-w` 等会改变输出通道的选项需要规范化或拦截，不能混入 SSE 数据；`--raw`、`--fail` 等影响响应解码和错误体的选项同样明确处理。
- 首版不执行文件引用、任意配置文件、上传、证书私钥路径、Cookie jar 写入等。给出具体参数和解决方法，可将 JSON 文件内容粘贴为字面请求体。
- 凭据和请求内容通过正确转义的 stdin cURL 配置传入，避免暴露在进程参数列表；配置编码器必须覆盖引号、反斜杠和换行，防止配置注入。
- 需要缓存的响应头使用私有临时目录，结束后清理；不把请求内容写入临时文件。
- 保持正常 TLS 验证；导入命令含 `-k` 时在发送区持续显示其生效状态。跨主机重定向不得透传自定义认证头，首版阻止此类携带认证的跳转并展示原因。
- 请求、Key、返回内容默认仅保存在本次页面会话内，不写 UserDefaults、应用日志或自动历史。离开页面时活动任务取消并保留状态直到页面会话释放，退出 App 清除。
- 后续若增加「记住 Key」，单独使用 macOS Keychain。默认导出调试包只含响应、指标、脱敏请求摘要和响应头；原始响应内容可能含敏感数据，导出入口说明包含范围。

## 7. 指标与验证

指标统一从点击发送开始计时，使用单调时钟：响应头到达、首个响应体字节、首个完整 SSE 事件、首个正文增量、总耗时、事件数和字节数。首文本耗时不命名为严格的模型 TTFT；不以 chunk 数估算 Token 数，也不把心跳算成输出速度。Token 只显示提供方返回的数据。

验证优先使用本地假 SSE 服务和固定测试数据，不依赖付费 API：

- 随机字节切分、中文/emoji、BOM、三种换行、多行 data、注释、id/retry、空 data、未完成尾部。
- Chat Completions 文本、多 choices、并行工具参数分片、usage、`[DONE]`、未知事件、坏 JSON、自定义增量/累计映射。
- 普通 JSON、HTML 错误、401/429、流内 error、首字节等待、心跳、半途断开、用户停止、超时和缓冲限制。
- stdout/stderr 同时高流量不会死锁，停止时回收进程，不将上一请求的迟到回调写入新结果。
- 变量替换、配置编码注入、文件选项拦截、重定向认证隔离、敏感数据不落盘及导出脱敏。
- 界面验证持续输出、查找、滚动锁定、窄窗口、复制与导出。功能开发完成后按仓库要求运行相关检查、构建 local、备份并安装本地 App、验证签名和二进制。

## 8. 首版交付边界

首版：独立入口、cURL 粘贴和显式变量、实际发送/停止、通用 SSE、Chat Completions 兼容聚合、四个响应视图、基础指标、错误保留、导出与离线重新解析、cURL 页跳转。

随后：Responses / Anthropic 适配、请求收藏与 Keychain、自定义映射预设。多模型并发对比、Prompt 评测、自动工具执行、完整 API 集合管理不列入本次首版。
