# WorkPilot 工作驾驶舱

入口：**Workspace → WorkPilot 工作驾驶舱**，也可用 `⌘K` 搜索“任务”“项目”“工作记录”“日报”或 `WorkPilot`。

## 工作台结构

主界面只有 **概览 / 记录 / 日报** 三个入口。

- **概览**：按所选日期与项目展示今日记录、待跟进、已完成和投入时间；左侧查看今日进展与 Git 自动发现，右侧查看待跟进和项目概况。空间不足时自动改为单列。普通图标、项目标识和进度条使用中性灰，已完成为柔和绿、待跟进为低饱和橙、阻塞为暗红。
- **记录**：原任务、工作记录和问题在同一份列表中处理。写一句即可保存，需要继续处理就勾选“待跟进”；点击圆圈标记完成，状态菜单可切换进行中、阻塞、已完成，普通记录也可转为待跟进。支持 `⌘↩` 快速记录，项目可不选，日期沿用当前选择。其他信息需要时再在编辑器的“更多”中补充。
- **日报**：汇总当天全部项目的素材，仍按“一句 skill 提示 + 日报原文”发送到 Codex。

项目不是同级页面。顶部项目菜单筛选概览和记录；点击概览中的项目卡片打开详情侧栏，查看完成情况、进展和待跟进，并可进入该项目的全部记录。“管理项目”收在项目菜单及“更多”中，可创建、编辑、关联 Git 仓库和归档。

概览统计口径：今日记录按事项的记录 / 完成日期统计，待跟进包含截至所选日期仍未完成的事项，已完成只计入所选日期明确完成的事项。项目完成率为已完成事项 / 所有需要跟进的事项，普通记录不计入分母；Git 提交和用时不会自动增加完成率。

## 旧数据兼容

旧任务、独立记录和问题保留原标识与原始内容，通过统一列表展示，无需手动搬运。任务及其关联完成记录只展示一次，原来的补充结果可展开查看。重新打开旧任务时，额外填写的完成结果会保留到说明中。新增事项始终保存在同一条记录上，后续切换状态不会生成第二条记录。归档不删除项目与记录；筛选菜单可查看已归档项目。

统一列表的删除会移除当前事项，删除旧任务时也移除其关联完成记录。编辑与删除前后的存储仍沿用原子保存和上一个有效版本备份。原有已保存日报不会被界面升级或后续工作记录覆盖，需要时点击“更新素材”。

## Git 提交自动采集

在项目编辑器点击“绑定本地仓库”，选择普通工作区或 Git worktree。保存后会扫描当天提交，App 运行期间每 5 分钟再采集一次；自动发现的刷新按钮用于手动补采其他日期。

- 扫描所有本地分支和引用中可见的提交，不执行 fetch，不联网。
- 按提交者时间所在的本地自然日筛选；作者邮箱默认读取 Git 的 `user.email`，项目中可指定其他作者邮箱。不会把其他作者的提交算作自己的工作。
- 采集提交摘要、短哈希、时间、文件数量和新增 / 删除行数，保存为待确认工作发现；点击“加入工作记录”后纳入日报。二进制文件计入文件数，其行数为 0；合并提交的统计可能为空。
- 使用仓库路径与完整提交哈希去重；同一仓库只能绑定一个项目。忽略会持久保存，可显示已忽略并恢复待确认。解绑不删除已有记录；已确认发现不会因再次扫描重复生成。
- 额外读取当前 Git status，展示未提交文件的状态与路径，不采集文件正文，不读取补丁正文。当前工作区变化不自动加入日报，不当作历史日期的完成证据。提交摘要可在工作记录中补充实际结果；首版不使用模型分析代码语义，也不会根据提交推断任务已经完成、功能已经上线或测试已经通过。
- 每次最多读取 500 条候选提交，输出上限 4 MB，整个仓库扫描限时 25 秒。失败会显示原因，不写入部分扫描结果；其他仓库可继续采集。

尚未提交的工作、会议、排查过程、阻塞和后续计划，都可直接写在统一记录里。项目进度根据事项状态计算，提交数量不等于完成率。

## Codex 工作会话自动发现

“自动发现”同时扫描 Git 与本机 Codex 会话。App 启动后以及每 5 分钟扫描当天，也可点击刷新扫描所选日期；数据目录沿用“设置 → Codex”的目录，默认使用 `CODEX_HOME` 或 `~/.codex`。

- 从 `sessions` 与 `archived_sessions` 的 JSONL 记录提取用户事项和最终答复，只收集已出现最终答复或完成事件的轮次。系统提示、开发者提示、工具输出、思考过程、中间更新、子代理输出不会进入工作记录。
- 按最终答复时间归入本机时区的自然日。长会话可在多天、多轮次持续工作，不把整个历史会话算到今天；同一轮的分页与归档副本按会话 ID + 轮次 ID 去重。
- 按会话的工作目录与已登记的项目仓库路径匹配，子目录也可匹配，嵌套项目优先选择更具体的路径。默认展示已匹配项目的候选；点击“另有 N 条未匹配项目的 Codex 会话”或在自动发现的更多菜单开启显示，可自行确认其他目录下的工作内容。不会通过关键词猜测私人聊天是否属于工作。
- 每条候选可展开查看事项、最终答复、来源目录，并可选择归属项目或打开原会话。“加入记录”后纳入该日期日报，“忽略”会保持忽略，重复扫描不会恢复或重复导入。已加入的工作记录保留手动修改，不随扫描覆盖。
- Codex 会话记录属于活动证据，不自动变成已完成、测试通过或已上线；项目完成率不自动增加。生成 WorkPilot 日报的会话会排除，避免日报内容再次被采集。
- 用户事项最多保留 4,000 字（每条消息最多 2,000 字），最终答复最多 8,000 字，超长时明确提示截取并提供原会话入口。不采集附件或图片内容。
- 采用后台增量读取；每次最多检查 2,000 个近期文件、读取 256 MiB，限时 20 秒；单条日志超过 1 MiB 时跳过。达到读取限制会显示提示，并在下一次扫描继续。文件读取异常会显示数量，不覆盖原文件。

Codex 用量统计仍只处理元数据和 Token；会话正文采集是 WorkPilot 的独立读取器。候选保存在本机工作区，只有主动加入记录后进入日报；发送给 Codex 的提示词继续只有约定句子和日报原文。

## 项目识别与计时

底部轻量状态栏中的“开始专注”选择项目后开始手动计时，优先于自动识别；“结束专注”后返回自动识别或停止状态。

点击“更多 → 自动计时设置”，选择运行中的应用并关联项目；找不到应用时可展开手动填写应用标识。开启“自动计时”后，前台应用唯一匹配一个未归档项目才累计时间；存在多个项目匹配时不自动归属，可手动专注。首版只按应用标识匹配，不读取窗口标题、浏览器内容、当前编辑文件或代码目录，因此同一编辑器中的多个项目需要手动选择。

每 15 秒保存用时，切换应用或结束专注时结算。无输入超过 2 分钟、屏幕或系统休眠、用户会话不活跃时暂停；采样间隔超过 30 秒不补算。退出 App 后不计时，重新启动需手动开启计时。意外退出可能丢失最后不足 15 秒的用时。跨午夜的记录按当天时间区间计算，不整段归给起始日。计时代表投入时间，不代表完成进度。

## 日报与 Codex Desktop

“日报”里的文字是整理素材，包含当天统一工作事项、已确认 Git 提交、问题与用时。可以直接补充，不必整理格式。“更新素材”重新汇总最新记录；已保存文字替换前会确认。素材不受项目与搜索筛选影响。历史日期汇总使用当前任务与问题状态，不是过去状态的快照。

点击“发送到 Codex 生成”会通过 `codex://threads/new` 在 Codex Desktop 打开预填的新对话，包含所选日期、素材和 `$daily-report-optimizer` skill 要求。桌面客户端提供的是草稿接收方式，仍需在 Codex 点击“发送”才开始生成。Yukino 不额外调用模型 API，也不会自动操作其他聊天。需要本机安装 Codex Desktop；skill 使用用户本机安装的版本，没有将个人 skill 内容复制进公共源码。

发送内容只有一句“请使用 $daily-report-optimizer（日报优化）skill，根据以下 WorkPilot 素材生成 YYYY-MM-DD 的中文工作日报。”，空一行后接日报素材原文。日期随所选日报变化，不附加说明、分隔标签或文件读取提示。长短素材都通过同一方式完整交接。只有点击交接后才把素材带到 Codex，之后沿用 Codex 选定的账号与模型处理。

## 本机保存与备份

记录会自动保存在这台 Mac，不需要手动点击保存。“更多”提供“备份记录”“从备份恢复”“打开本机保存位置”。它们是备用功能，日常记录无需使用。“落盘”只是写入本机文件，界面不再使用这个术语。

数据位于 `~/Library/Application Support/YukinoTools/WorkPilot/workspace.json`。保存采用原子替换，上一个有效版本位于同目录的 `workspace.backup.json`。读取失败时保留原文件并禁止覆盖，可以保存副本后恢复有效 JSON 备份。恢复前会确认替换，并先保存当前原文件的独立恢复副本。备份包含仓库路径、作者邮箱设置和工作内容，按需保管。数据上限 20 MB。公共与本地构建使用同一份 WorkPilot 数据。
