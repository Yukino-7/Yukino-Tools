# OpenRouter 日报迁移分析

分析与迁移日期：2026-09-30。日报已迁入 App，随 v0.4.0 发布。

## 结论

已迁移到 Yukino Tools，保持 Markdown 文件作为最终报告。Swift 实现获取、比较、生成与存储，原生阅读组件渲染日报使用的 Markdown 格式。无需启动原项目的 React 页面或 Spring Boot 服务，也无需让发布包依赖用户安装 Python。

## 已确认的现有行为

Yukino 项目的核心实现位于 `pyutils/openrouter_daily/report.py`，共 805 行，只使用 Python 标准库。仓库中共有 27 份历史日报，日期范围为 2026-08-29 至 2026-09-30。

生成过程为：读取模型列表 → 解析免费榜单 → 与已有历史报告比较 → 输出 `YYYY-MM-DD.md`。日期使用 Asia/Shanghai。历史基线实际选择早于目标日期的最近报告，未必正好是前一天。

| 内容 | 数据来源和现有行为 |
| --- | --- |
| 免费模型总览 | `/api/v1/models`，按照 prompt 与 completion 两项价格均为零识别 |
| 免费模型周调用量 TOP 5 | 从 discover 页面 HTML 抓取，再按模型名补充提供方和模型 ID |
| 新增与移出 | 比较历史报告全量表中的模型 ID |
| 榜单变化 | 从历史 Markdown 解析 TOP 5，比较周 Token 数与排名 |
| 能力列表 | 上下文、输入/输出类型、工具调用及结构化输出 |
| 全平台榜首 | 原实现保留“数据未抓取”占位，没有实际数据 |

2026-09-30 只读联网检查：模型接口与 discover 页面均返回 HTTP 200；模型接口返回有效 `data` 数组，discover HTML 中包含免费模型和周 Token 表格标记。随后已使用这些真实响应完成 Swift 解析与原生联网生成；此检查不代表未来可用性。

官方模型接口说明：[OpenRouter models](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)。榜单来源：[discover](https://openrouter.ai/discover?lane=free)。当前脚本不调用推理接口，不使用模型生成日报正文。

## 迁移时应修正的问题

1. **零价格类型**：局部离线验证确认，字符串 `"0"` 会被识别为免费，而数值 `0` 因 `or "1"` 回退被识别为付费。新实现应区分缺失值与合法零值。
2. **缺少上下文**：局部离线验证确认，上下文缺失时回退到字符串 `"?"`，随后使用数值千分位格式会抛出 ValueError。未知值应显示 `—`。
3. **失败与零值**：接口失败时，原报告头部仍可能写入零模型数。应显示“数据不可用”，保留历史，避免被理解为所有模型都下架。
4. **历史日期**：`--date` 只改变报告日期，并不会获取那个日期的历史网络数据。App 应只生成当日报告；历史内容通过读取已有文件获取。
5. **抓取脆弱性**：榜单依赖 HTML 和模型名称匹配，页面变化及重名都可能造成错配。匹配不明确时保留未知值；榜单不足五条时标记降级。
6. **重复函数**：Token 格式化、历史榜单读取、榜单对比等四个函数各定义两次，后定义覆盖前定义，应在迁移时统一实现。
7. **代理与来源说明**：原脚本强制绕过 OpenRouter 的系统代理。App 建议遵循系统网络配置。新生成报告的署名应为 Yukino Tools，历史报告保持原文。

## 建议的 App 页面

AI 分组新增 **OpenRouter 日报**。

- 历史列表默认收起，优先显示当日；按需展开日期列表，旧报告支持一键回到今日。
- 右侧：默认 Markdown 阅读，支持标题、引用、列表、粗体、代码、删除线、链接和表格；TOP 5 与榜单对比根据可用宽度布局，窄阅读区采用卡片，无横向滚动；全量模型表保留横向滚动。
- 顶部：生成今日日报、刷新历史、导入历史目录、预览/源码切换、复制和导出 `.md`。
- 获取中显示进度，异常时明确提示失败的数据源；离线仍可阅读已有历史。
- 重新生成同日内容时明确区分已有报告与新结果，不静默覆盖。

普通 SwiftUI Text 的 Markdown 显示不足以完整布局这些多列表格，需要独立的原生块级 Markdown 阅读组件。

## 推荐实现拆分

| 部分 | 责任 |
| --- | --- |
| OpenRouter 数据服务 | URLSession 获取模型 JSON 和榜单 HTML，超时、响应大小限制、字段校验、降级 |
| 报告生成服务 | 模型识别、排序、历史变化、榜单对比、Markdown 转义和正文生成 |
| 报告存储 | App 的 Application Support 目录下保存日期 Markdown 和可用数据快照；导入原历史报告副本 |
| 日报状态与界面 | 日期选择、生成进度、错误、预览/源码、复制、导入和导出 |
| Markdown 阅读组件 | 原生排版，保留文本选择和链接；表格横向滚动 |

保留 `.md` 为可移植文件；新日报另存结构化快照，避免新报告的日间比较长期依赖 Markdown 正则解析。导入的旧报告仍需兼容原格式。报表必须标明实际基线日期：日期不相邻时使用“对比上次报告”，不称为“昨日”。

首版推荐手动生成与历史阅读。全天自动生成、App 关闭后仍运行等属于另一个明确的调度需求，不由文件底部“每日自动生成”的历史文案推断。

## 已落地与验证

- `OpenRouterReportService`：URLSession 并行获取两项公开数据，遵循系统网络配置；每次请求 20 秒超时，JSON/HTML 大小上限分别为 5 MB / 8 MB。支持真实接口的 `~provider/model-latest` 别名，拒绝重复或无效 ID；重名时不补写无法确认的模型 ID。
- `DailyReportStore`：按日期保存 Markdown 和 JSON 快照；摘要匹配后采用快照，否则从旧 Markdown 重建历史基线。跳过不可读历史，导入不覆盖已有日期，更新同日备份到 `Revisions`。
- `MarkdownDocument` / `MarkdownReader`：日报所需块级解析与 SwiftUI 原生布局，没有 WebView、脚本或远程图片加载。源码使用只读 AppKit 编辑器；这是日报格式支持，并非完整 CommonMark 编辑器。
- `OpenRouterDailyView`：AI 侧栏、命令搜索与菜单栏入口；日期列表、手动生成、进度/取消、导入、阅读/源码、复制、导出和同日更新提示。
